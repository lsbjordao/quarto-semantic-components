Semantic Blocks — exemplo

Esta página demonstra todos os componentes da extensão.

Steps — numerado

A sintaxe é deliberadamente próxima do Vocs: :::steps funciona como um fenced div do Pandoc/Quarto.

  1. Instale a extensão

    Copie a pasta _extensions/semantic-blocks para o projeto ou instale o pacote da forma usual do Quarto.

  2. Ative o filtro

    Inclua semantic-blocks em filters no YAML do documento ou do projeto.

  3. Escreva normalmente

    Cada título dentro de steps inicia uma nova etapa. O conteúdo da etapa continua sendo Markdown comum.

Steps — bolinhas

Use type="dots" para trocar os números por nós circulares preenchidos.

  • Baixe os dados

    Faça a ingestão das fontes necessárias.

  • Valide

    Execute as verificações de consistência.

  • Publique

    Gere o produto final.

Steps — estilo histórico Git

type="git" usa uma linha vertical com nós semelhantes a commits.

  • feat: cria estrutura inicial

    Primeiro estado funcional do projeto.

  • refactor: reorganiza módulos

    A arquitetura é simplificada sem alterar o resultado esperado.

  • release: publica versão 1.0

    Versão estável entregue.

File tree

A sintaxe segue a ideia do Vocs: listas aninhadas e + antes do nome para declarar explicitamente uma pasta. Uma pasta também é inferida quando o item possui filhos.

  • README.md documentação principal
  • quarto.yml configuração do projeto
  • src código-fonte
    • main.ts ponto de entrada destacado
    • utils.ts utilitários
    • components componentes reutilizáveis
      • Button.ts
      • Card.ts
  • public arquivos estáticos
    • logo.svg
    • robots.txt

File tree mínimo

Não é obrigatório escrever + quando a hierarquia já deixa claro que o item é uma pasta.

  • project
    • index.qmd
    • styles.css
    • assets
      • logo.svg

Compatibilidade com outros formatos

Os componentes são construídos sobre nós nativos da AST do Pandoc. No HTML, o CSS fornece o tratamento visual completo. Em DOCX e PDF, steps continua sendo uma lista ordenada ou não ordenada, circle-list continua sendo uma lista ordenada e file-tree continua sendo uma lista hierárquica legível.
