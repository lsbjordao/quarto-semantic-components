Quarto Semantic Components — exemplos

Esta página demonstra os componentes da extensão Quarto Semantic Components. Em cada seção, o código-fonte aparece antes do resultado renderizado.

Defaults de projeto no _quarto.yml

Este próprio repositório usa defaults compartilhados:

extensions:
  badge:
    - key: stable
      label: Estável
      type: success
      appearance: solid
      icon: "✓"
    - key: experimental
      label: Experimental
      type: info
      appearance: outline
      icon: "⚗"
    - key: deprecated
      label: Deprecated
      type: danger
      appearance: soft
      icon: "!"

  steps:
    dot-color: "#8c959f"
    dot-size: "0.72rem"
    line-color: "#9aa0a6"
    line-width: "1.5px"

  file-tree:
    icons: devicon
    expanded: true

  git-tree:
    direction: TB
    line-color: "#9aa0a6"
    line-width: "2px"
    node-size: "0.68rem"
    lane-gap: "0.82rem"
    row-height: "36px"

A precedência é defaults do projeto → preset → componente → item individual.

Badges inline

O shortcode público é badge. Como mcanouil/quarto-badge usa o mesmo nome, o projeto deve escolher qual extensão de badge deseja usar.

Presets definidos no projeto

{{< badge stable >}}
{{< badge experimental >}}
{{< badge deprecated >}}
{{< badge "Release estável" key="stable" >}}

Output:

✓ Estável ⚗ Experimental ! Deprecated ✓ Release estável

Personalização livre

{{< badge "Beta" >}}
{{< badge "Estável" type="success" icon="✓" >}}
{{< badge "Experimental" type="warning" appearance="outline" >}}
{{< badge "v0.7.0" type="accent" appearance="solid" >}}

Output:

Beta ✓ Estável Experimental v0.7.0

Forma AST-native

[AST-native]{.badge key="stable" appearance="outline" size="md"}

Output: AST-native

Git tree — DAG de commits

O gráfico representa commits e relações parent → child. Branches saem de nós; merges terminam em nós.

Sintaxe simples — direção TB

::: {.git-tree direction="TB"}
- `main` initial commit
- `main` cria a arquitetura base
  - `feature/icons` abre o branch de ícones
  - `feature/icons` adiciona Devicon
    - `docs/icons` documenta os providers
    - `docs/icons` adiciona exemplos
  - `feature/icons` merge docs/icons
  - `feature/icons` adiciona links em arquivos
- `main` merge feature/icons
- `main` inicia componentes inline
  - `feature/badges` cria badge
  - `feature/badges` adiciona customização visual
    - `test/badges` cobre variantes
    - `test/badges` cobre links
  - `feature/badges` merge test/badges
- `main` merge feature/badges
- `main` release v0.7.0
:::

Output:

main initial commit
main cria a arquitetura base
feature/icons abre o branch de ícones
feature/icons adiciona Devicon
docs/icons documenta os providers
docs/icons adiciona exemplos
feature/icons merge docs/icons
feature/icons adiciona links em arquivos
main merge feature/icons
main inicia componentes inline
feature/badges cria badge
feature/badges adiciona customização visual
test/badges cobre variantes
test/badges cobre links
feature/badges merge test/badges
main merge feature/badges
main release v0.7.0

Mesmo DAG — direção BT

BT apenas inverte a direção de leitura; as relações entre commits permanecem as mesmas.

::: {.git-tree direction="BT"}
- `main` initial commit
- `main` arquitetura base
  - `feature/api` cria API
  - `feature/api` implementa endpoints
- `main` merge feature/api
- `main` release
:::

Output:

main release
main merge feature/api
feature/api implementa endpoints
feature/api cria API
main arquitetura base
main initial commit

DAG explícito — ids, parents, tag e HEAD

Quando a indentação não é suficiente, declare a história explicitamente. parents= prevalece sobre a inferência automática.

:::git-tree
- `main`{#c1} initial commit
- `main`{#c2 parent="c1"} arquitetura base
  - `feature/badges`{#c3 parent="c2"} cria badge
  - `feature/badges`{#c4 parent="c3"} customização visual
    - `test/badges`{#c5 parent="c4"} cobre variantes
    - `test/badges`{#c6 parent="c5"} cobre links
  - `feature/badges`{#c7 parents="c4,c6"} merge test/badges
- `main`{#c8 parents="c2,c7" tag="v0.7.0" head="true"} merge feature/badges
:::

Output:

main initial commit
main arquitetura base
feature/badges cria badge
feature/badges customização visual
test/badges cobre variantes
test/badges cobre links
feature/badges merge test/badges
main HEAD v0.7.0 merge feature/badges

Inspiração e formatos

As ideias de Steps e File Tree foram inspiradas em componentes do Vocs, mas a implementação é própria e orientada ao AST do Pandoc.

  • HTML: apresentação completa, badges, file tree interativo, tooltips e Git DAG em SVG;
  • PDF: conteúdo estrutural e links são preservados;
  • DOCX: listas, links e texto permanecem editáveis.
