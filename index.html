Quarto Semantic Components — exemplos

Esta página demonstra os componentes da extensão Quarto Semantic Components. Em cada seção, o código-fonte aparece antes do resultado renderizado.

Defaults de projeto no _quarto.yml

Este próprio repositório usa defaults compartilhados:

extensions:
  badge:
    - key: stable
      label: Estável
      type: success
      appearance: solid
      icon: "✓"
    - key: experimental
      label: Experimental
      type: info
      appearance: outline
      icon: "⚗"
    - key: deprecated
      label: Deprecated
      type: danger
      appearance: soft
      icon: "!"

  steps:
    dot-color: "#8c959f"
    dot-size: "0.72rem"
    line-color: "#9aa0a6"
    line-width: "1.5px"

  file-tree:
    icons: devicon
    expanded: true

  git-tree:
    direction: TB
    line-color: "#9aa0a6"
    line-width: "2px"
    node-size: "0.68rem"
    lane-gap: "0.82rem"
    row-height: "36px"
    content-gap: "0.55rem"

  article:
    radius: "0.75rem"
    padding: "1rem 1.1rem"
    accent: none

A precedência é defaults do projeto → preset → componente → item individual.

Badges inline

O shortcode público é badge. Como mcanouil/quarto-badge usa o mesmo nome, o projeto deve escolher qual extensão de badge deseja usar.

Presets definidos no projeto

{{< badge stable >}}
{{< badge experimental >}}
{{< badge deprecated >}}
{{< badge "Release estável" key="stable" >}}

Output:

✓ Estável ⚗ Experimental ! Deprecated ✓ Release estável

Personalização livre

{{< badge "Beta" >}}
{{< badge "Estável" type="success" icon="✓" >}}
{{< badge "Experimental" type="warning" appearance="outline" >}}
{{< badge "v0.10.3" type="accent" appearance="solid" >}}

Output:

Beta ✓ Estável Experimental v0.10.3

Forma AST-native

[AST-native]{.badge key="stable" appearance="outline" size="md"}

Output: AST-native

Steps — numerado

Todos os exemplos de steps usam quatro etapas.

:::steps
## Instale a extensão
Use `quarto add lsbjordao/quarto-semantic-components`.

## Ative o filtro
Inclua `semantic-components` em `filters`.

## Configure os componentes
Defina defaults no `_quarto.yml` se desejar.

## Escreva normalmente
Cada heading inicia uma etapa.
:::

Output:

  1. Instale a extensão

    Use quarto add lsbjordao/quarto-semantic-components.

  2. Ative o filtro

    Inclua semantic-components em filters.

  3. Configure os componentes

    Defina defaults no _quarto.yml se desejar.

  4. Escreva normalmente

    Cada heading inicia uma etapa.

Git tree — DAG de commits

O gráfico representa commits e relações parent → child. Branches saem de nós; merges terminam em nós; tag e descrição acompanham a lane do commit.

Sintaxe simples — direção TB

::: {.git-tree direction="TB"}
- `main` initial commit
- `main` cria a arquitetura base
  - `feature/icons` abre o branch de ícones
  - `feature/icons` adiciona Devicon
    - `docs/icons` documenta os providers
    - `docs/icons` adiciona exemplos
  - `feature/icons` merge docs/icons
  - `feature/icons` adiciona links em arquivos
- `main` merge feature/icons
- `main` inicia componentes inline
  - `feature/badges` cria badge
  - `feature/badges` adiciona customização visual
    - `test/badges` cobre variantes
    - `test/badges` cobre links
  - `feature/badges` merge test/badges
- `main` merge feature/badges
- `main` release v0.10.3
:::

Output:

main initial commit
main cria a arquitetura base
feature/icons abre o branch de ícones
feature/icons adiciona Devicon
docs/icons documenta os providers
docs/icons adiciona exemplos
feature/icons merge docs/icons
feature/icons adiciona links em arquivos
main merge feature/icons
main inicia componentes inline
feature/badges cria badge
feature/badges adiciona customização visual
test/badges cobre variantes
test/badges cobre links
feature/badges merge test/badges
main merge feature/badges
main release v0.10.3

Mesmo DAG — direção BT

::: {.git-tree direction="BT"}
- `main` initial commit
- `main` arquitetura base
  - `feature/api` cria API
  - `feature/api` implementa endpoints
- `main` merge feature/api
- `main` release
:::

Output:

main release
main merge feature/api
feature/api implementa endpoints
feature/api cria API
main arquitetura base
main initial commit

DAG explícito — ids, parents, tag e HEAD

:::git-tree
- `main`{#c1} initial commit
- `main`{#c2 parent="c1"} arquitetura base
  - `feature/badges`{#c3 parent="c2"} cria badge
  - `feature/badges`{#c4 parent="c3"} customização visual
    - `test/badges`{#c5 parent="c4"} cobre variantes
    - `test/badges`{#c6 parent="c5"} cobre links
  - `feature/badges`{#c7 parents="c4,c6"} merge test/badges
- `main`{#c8 parents="c2,c7" tag="v0.10.3" head="true"} merge feature/badges
:::

Output:

main initial commit
main arquitetura base
feature/badges cria badge
feature/badges customização visual
test/badges cobre variantes
test/badges cobre links
feature/badges merge test/badges
main HEAD v0.10.3 merge feature/badges

Article

article é a primitive genérica para conteúdo autocontido. O HTML externo é sempre <article>.

Genérico — apenas borda arredondada

:::article
## Nota técnica
Este é o `article` padrão, sem accent e sem collapse.
:::

Output:

Nota técnica

Este é o article padrão, sem accent e sem collapse.

Accent esquerdo com pontas arredondadas

::: {.article accent="left" variant="warning"}
## Atenção
A barra lateral é opcional. O componente continua sendo um `article`.
:::

Output:

Atenção

A barra lateral é opcional. O componente continua sendo um article.

Também é possível controlar diretamente accent-color e accent-width.

Collapsed por padrão

::: {.article
  collapsible="true"
  summary="Detalhes técnicos"
  expanded="false"}

O conteúdo está dentro de um `details` nativo, mas o elemento externo continua sendo `article`.

- Markdown normal
- listas
- código
- outros componentes

:::

Output:

Detalhes técnicos

O conteúdo está dentro de um details nativo, mas o elemento externo continua sendo article.

  • Markdown normal
  • listas
  • código
  • outros componentes

Expanded + accent

::: {.article
  accent="left"
  variant="note"
  collapsible="true"
  summary="Metodologia"
  expanded="true"}

Este exemplo começa expandido e combina o accent com o collapse.

:::

Output:

Metodologia

Este exemplo começa expandido e combina o accent com o collapse.

Exemplo — changelog dentro de um article

:::article

### Added
- Accent esquerdo opcional em `article`.
- Collapse/expand nativo.

### Changed

- Tags e descrições acompanham a lane do commit.

Inspiração e formatos

As ideias de Steps e File Tree foram inspiradas em componentes do Vocs, mas a implementação é própria e orientada ao AST do Pandoc.

  • HTML: apresentação completa, badges, file tree interativo, tooltips, Git DAG em SVG e o elemento semântico article;
  • PDF: conteúdo estrutural e links são preservados;
  • DOCX: listas, headings, links e texto permanecem editáveis.
