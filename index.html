Quarto Semantic Components — exemplos

Esta página demonstra os componentes da extensão Quarto Semantic Components. Em cada seção, o código-fonte aparece antes do resultado renderizado.

Defaults de projeto no _quarto.yml

Este próprio repositório usa defaults compartilhados:

extensions:
  badge:
    - key: stable
      label: Estável
      type: success
      appearance: solid
      icon: "✓"
    - key: experimental
      label: Experimental
      type: info
      appearance: outline
      icon: "⚗"
    - key: deprecated
      label: Deprecated
      type: danger
      appearance: soft
      icon: "!"

  steps:
    dot-color: "#8c959f"
    dot-size: "0.72rem"
    line-color: "#9aa0a6"
    line-width: "1.5px"

  file-tree:
    icons: devicon
    expanded: true

  git-tree:
    line-color: "#9aa0a6"
    line-width: "2px"
    node-size: "0.68rem"
    lane-gap: "0.82rem"

A precedência é defaults do projeto → preset → componente → item individual.

Badges inline

O shortcode público é badge. Como mcanouil/quarto-badge usa o mesmo nome, o projeto deve escolher qual extensão de badge deseja usar.

Presets definidos no projeto

{{< badge stable >}}
{{< badge experimental >}}
{{< badge deprecated >}}
{{< badge "Release estável" key="stable" >}}

Output:

✓ Estável ⚗ Experimental ! Deprecated ✓ Release estável

Personalização livre

{{< badge "Beta" >}}
{{< badge "Estável" type="success" icon="✓" >}}
{{< badge "Experimental" type="warning" appearance="outline" >}}
{{< badge "v0.6.7" type="accent" appearance="solid" >}}
{{< badge "Custom"
  bg="#111827" fg="#f9fafb" border="#60a5fa"

  padding="0.22em 0.75em" weight="750"

Forma AST-native

A forma AST-native também usa apenas badge:

[AST-native]{.badge key="stable" appearance="outline" size="md"}

Output: AST-native

Steps — numerado

Todos os exemplos de steps usam quatro etapas.

:::steps
## Instale a extensão

Use `quarto add lsbjordao/quarto-semantic-components`.

## Ative o filtro

Inclua `semantic-components` em `filters`.

## Configure os componentes

Defina defaults no `_quarto.yml` se desejar.

## Escreva normalmente

Cada heading inicia uma etapa.
:::

Output:

  1. Instale a extensão

    Use quarto add lsbjordao/quarto-semantic-components.

  2. Ative o filtro

    Inclua semantic-components em filters.

  3. Configure os componentes

    Defina defaults no _quarto.yml se desejar.

  4. Escreva normalmente

    Cada heading inicia uma etapa.

Git tree

A sintaxe é uma lista aninhada; no HTML, a extensão desenha lanes, nós, branches e merges em SVG.

:::git-tree
- `main` initial commit
- `main` cria a arquitetura base
  - `feature/icons` abre o branch de ícones
  - `feature/icons` adiciona Devicon
    - `docs/icons` documenta os providers
    - `docs/icons` adiciona exemplos
  - `feature/icons` adiciona links em arquivos
- `main` merge feature/icons
- `main` inicia componentes inline
  - `feature/badges` cria badge
  - `feature/badges` adiciona customização visual
    - `test/badges` cobre variantes
    - `test/badges` cobre links
- `main` merge feature/badges
- `main` release v0.6.7
:::

Output:

main initial commit
main cria a arquitetura base
feature/icons abre o branch de ícones
feature/icons adiciona Devicon
docs/icons documenta os providers
docs/icons adiciona exemplos
feature/icons adiciona links em arquivos
main merge feature/icons
main inicia componentes inline
feature/badges cria badge
feature/badges adiciona customização visual
test/badges cobre variantes
test/badges cobre links
main merge feature/badges
main release v0.6.7

File tree — pastas expansíveis e colapsáveis

Em HTML, toda pasta que contém filhos pode ser aberta e fechada. O default do projeto é expanded: true, mas ele pode ser alterado no _quarto.yml, no bloco inteiro ou por diretório. Clique no chevron ou no nome da pasta; links dentro da pasta continuam navegando normalmente.

::: {.file-tree expanded="false"}
- [+src]{expanded="true"}
  - +components
    - Button.ts
    - Card.ts
  - app.ts
  - styles.css
- [+docs]{open="false"}
  - index.qmd
  - api.qmd
- [+data]{collapsed="true"}
  - raw.csv
  - processed.parquet
:::

Output:

  • src
    • components
      • Button.ts
      • Card.ts
    • app.ts
    • styles.css
  • docs
    • index.qmd
    • api.qmd
  • data
    • raw.csv
    • processed.parquet

Em PDF e DOCX, a hierarquia permanece sempre visível; a interação é exclusiva do HTML.

File tree — texto normal ou inline code

O file-tree preserva a escolha do autor. Um nome sem crases fica como texto normal; um nome entre crases recebe a semântica/estilo de inline code. A mesma regra vale para links.

:::file-tree
- analysis.R texto normal
- `pipeline.py` inline code
- [app.ts](https://github.com/lsbjordao/quarto-semantic-components) link normal
- [`steps.lua`](https://github.com/lsbjordao/quarto-semantic-components/blob/main/_extensions/semantic-components/steps.lua) link + inline code
:::

Output:

  • analysis.R texto normal
  • pipeline.py inline code
  • app.ts link normal
  • steps.lua link + inline code

File tree — tooltip de informação

tooltip= ou info= adiciona um pequeno ícone de informação em HTML.

:::file-tree
- [analysis.R]{tooltip="Script principal de análise em R"}
- [`pipeline.py`]{tooltip="Pipeline de ingestão e validação"}
- [app.ts](https://github.com/lsbjordao/quarto-semantic-components){tooltip="Abrir o repositório"}
- [`file-tree.lua`](https://github.com/lsbjordao/quarto-semantic-components/blob/main/_extensions/semantic-components/file-tree.lua){info="Ver a implementação do componente"}

Inspiração e formatos

As ideias de Steps e File Tree foram inspiradas em componentes de documentação do Vocs, mas a implementação desta extensão é própria e orientada ao AST do Pandoc.

  • HTML: apresentação completa, ícones, badges, tooltips, árvores colapsáveis e Git tree em SVG;
  • PDF: conteúdo estrutural e links são preservados;
  • DOCX: listas, links e texto permanecem editáveis.
