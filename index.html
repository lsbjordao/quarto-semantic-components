Quarto Semantic Components — examples

This page demonstrates the Quarto Semantic Components extension. In each section, the source code appears before the rendered output.

Project defaults in _quarto.yml

This repository uses shared defaults:

extensions:
  badge:
    - key: stable
      label: Stable
      type: success
      appearance: solid
      icon: "✓"
    - key: experimental
      label: Experimental
      type: info
      appearance: outline
      icon: "⚗"
    - key: deprecated
      label: Deprecated
      type: danger
      appearance: soft
      icon: "!"

  steps:
    dot-color: "#8c959f"
    dot-size: "0.72rem"
    line-color: "#9aa0a6"
    line-width: "1.5px"

  file-tree:
    icons: devicon
    expanded: true
    indent: "1.8rem"

  git-tree:
    direction: TB
    line-color: "#9aa0a6"
    line-width: "2px"
    node-size: "0.68rem"
    lane-gap: "0.82rem"
    row-height: "36px"
    content-gap: "0.55rem"

  article:
    radius: "0.75rem"
    padding: "1rem 1.1rem"
    accent: none

Precedence is project defaults → preset → component → individual item.

Badges

The public shortcode is badge. Since mcanouil/quarto-badge uses the same name, the project must choose which badge extension to use.

Presets defined in the project

{{< badge stable >}}
{{< badge experimental >}}
{{< badge deprecated >}}
{{< badge "Stable release" key="stable" >}}

Output:

✓ Stable ⚗ Experimental ! Deprecated ✓ Stable release

Free customization

{{< badge "Beta" >}}
{{< badge "Stable" type="success" icon="✓" >}}
{{< badge "Experimental" type="warning" appearance="outline" >}}
{{< badge "v0.10.9" type="accent" appearance="solid" >}}

Output:

Beta ✓ Stable Experimental v0.10.9

Forma AST-native

[AST-native]{.badge key="stable" appearance="outline" size="md"}

Output: AST-native

Steps

Numbered

All steps examples use four steps. In numbered mode, the edge is also continuous between circle centers and stays behind the markers; the inside follows the theme surface.

:::steps
## Install the extension
Use `quarto add lsbjordao/quarto-semantic-components`.

## Enable the filter
Add `semantic-components` to `filters`.

## Configure the components
Set defaults in `_quarto.yml` if desired.

## Write normally
Each heading starts a step.
:::

Output:

  1. Install the extension

    Use quarto add lsbjordao/quarto-semantic-components.

  2. Enable the filter

    Add semantic-components to filters.

  3. Configure the components

    Set defaults in _quarto.yml if desired.

  4. Write normally

    Each heading starts a step.

Dots

Dots look hollow by default: the center uses the theme surface color, hiding the continuous edge that passes behind them. dot-color controls the outline and dot-fill enables explicit fill.

Project default

::: {.steps type="dots"}
## Extract
Download the data.

## Validate
Validate the records.

## Transform
Prepare the data.

## Publish
Publish the result.
:::

Output:

  • Extract

    Download the data.

  • Validate

    Validate the records.

  • Transform

    Prepare the data.

  • Publish

    Publish the result.

  line-color="#9aa0a6"}

## Prepare
First step.

## Process
Second step.

## Review
Third step.

## Publish
Fourth step.

:::

Example — timeline with Steps dots

  dot-size="0.78rem"}

API freeze for final testing.

## [2026-09]{.badge type="success" appearance="solid" size="xs"} Release {dot-color="#16a34a"}

Git tree

The graph represents commits and parent → child relationships. Branches split from nodes; merges end at nodes; the tag and description follow the commit lane.

Simple syntax — TB direction

::: {.git-tree direction="TB"}
- `main` initial commit
- `main` creates the base architecture
  - `feature/icons` opens the icons branch
  - `feature/icons` adds Devicon
    - `docs/icons` documents providers
    - `docs/icons` adds examples
  - `feature/icons` merge docs/icons
  - `feature/icons` adds file links
- `main` merge feature/icons
- `main` starts inline components
  - `feature/badges` creates badge
  - `feature/badges` adds visual customization
    - `test/badges` covers variants
    - `test/badges` covers links
  - `feature/badges` merge test/badges
- `main` merge feature/badges
- `main` release v0.10.9
:::

Output:

main initial commit
main creates the base architecture
feature/icons opens the icons branch
feature/icons adds Devicon
docs/icons documents providers
docs/icons adds examples
feature/icons merge docs/icons
feature/icons adds file links
main merge feature/icons
main starts inline components
feature/badges creates badge
feature/badges adds visual customization
test/badges covers variants
test/badges covers links
feature/badges merge test/badges
main merge feature/badges
main release v0.10.9

Same DAG — BT direction

::: {.git-tree direction="BT"}
- `main` initial commit
- `main` base architecture
  - `feature/api` creates API
  - `feature/api` implementa endpoints
- `main` merge feature/api
- `main` release
:::

Output:

main release
main merge feature/api
feature/api implementa endpoints
feature/api creates API
main base architecture
main initial commit

Explicit DAG — ids, parents, tag, and HEAD

:::git-tree
- `main`{#c1} initial commit
- `main`{#c2 parent="c1"} base architecture
  - `feature/badges`{#c3 parent="c2"} creates badge
  - `feature/badges`{#c4 parent="c3"} visual customization
    - `test/badges`{#c5 parent="c4"} covers variants
    - `test/badges`{#c6 parent="c5"} covers links
  - `feature/badges`{#c7 parents="c4,c6"} merge test/badges
- `main`{#c8 parents="c2,c7" tag="v0.10.9" head="true"} merge feature/badges
:::

Output:

main initial commit
main base architecture
feature/badges creates badge
feature/badges visual customization
test/badges covers variants
test/badges covers links
feature/badges merge test/badges
main HEAD v0.10.9 merge feature/badges

Horizontal indentation

The per-level indentation can be changed with indent. This gallery defaults to 1.8rem.

::: {.file-tree indent="1rem"}
- +src
  - +components
    - Button.ts
    - Card.ts
  - app.ts
- +database
  - schema.sql
:::

Output:

  • src
    • components
      • Button.ts
      • Card.ts
    • app.ts
  • database
    • schema.sql

Use larger values, such as indent="2.4rem", to spread the hierarchy out more visually.

Article

article is the generic primitive for self-contained content. The outer HTML element is always <article>.

Generic — rounded border only

:::article
## Technical note
This is the default `article`, with no accent and no collapse.
:::

Output:

Technical note

This is the default article, with no accent and no collapse.

Left accent with rounded ends

::: {.article accent="left" accent-color="warning"}
## Attention
The side accent is optional. The component remains an `article`.
:::

Output:

Attention

The side accent is optional. The component remains an article.

Use accent-color="warning", note, danger, success, important, or any CSS color such as #8b5cf6. accent-width controls the thickness.

Collapsed by default

::: {.article
  collapsible="true"
  summary="Technical details"
  expanded="false"}

The content is inside a native `details`, while the outer element remains `article`.

- normal Markdown
- listas
- code
- other components

:::

Output:

Technical details

The content is inside a native details, while the outer element remains article.

  • normal Markdown
  • listas
  • code
  • other components

Expanded + accent

::: {.article
  accent="left"
  accent-color="note"
  collapsible="true"
  summary="Methodology"
  expanded="true"}

This example starts expanded and combines accent with collapse.

:::

Output:

Methodology

This example starts expanded and combines accent with collapse.

Inspiration and formats

The Steps and File Tree ideas were inspired by Vocs components, but the implementation is original and Pandoc-AST-oriented.

  • HTML: full presentation, badges, interactive file tree, info, Git DAG in SVG, and the semantic article element;
  • PDF: structural content and links are preserved;
  • DOCX: lists, headings, links, and text remain editable.
